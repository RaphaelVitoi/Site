# .hermes.md — slot de contexto do harness para o projeto `Site`

> **Por que este arquivo existe.** O harness carrega **um** tipo de contexto de
> projeto, primeiro-vencedor: `.hermes.md`/`HERMES.md` → `AGENTS.md` →
> `CLAUDE.md` → `.cursorrules`. Sem este arquivo, `AGENTS.md` (1.485 B) ocupa o
> slot e os **86.178 chars** de `CLAUDE.md` **não chegam ao prompt** — medido:
> `CLAUDE.md` aparece como `shadowed` em toda medição.
>
> **Este arquivo não substitui a governança.** Ele é o **roteador**: carrega o
> essencial que precisa estar *antes* de agir, e Indexa o resto para leitura sob
> demanda. `CLAUDE.md` continua sendo o canônico — a fonte única não mudou de
> lugar, e esta ponte não o substitui nem o copia.

## 1. Essential que vive no prompt (pré-condição, não consulta)

O que abaixo **não pode** esperar por gatilho: é o que previne o erro, e o
gatilho que dispara o erro é justamente o que estas regras governam.

### Soberania e identidade

- **Tier 0 — Raphael Vitoi** é árbitro maior e soberania/vértice absolutos.
  Autoridade, arquitetura, código, algoritmos e propriedade intelectual emanam
  dele. Nenhum modelo é proprietário; são instrumentos cognitivos sob consentimento.
- **`.claude/`, `.gemini/`, `CLAUDE.md`, `GEMINI.md`** — nomenclatura de
  convenção. **Nenhuma confere propriedade a fornecedor de IA.**
- **Nenhum harness tem tier.** §1.3 classifica **modelos**; §1.5 classifica
  **harnesses**. Não atribua tier a um harness (Claude Code, Antigravity 2.0,
  Codex CLI, Hermes Agent). Todo harness tem função; todo modelo tem elegibilidade
  por **papel**, nunca por estar em catálogo de provider.

### Lei de Concorrência — Zero-Interferência

**Dois modelos de fronteira NÃO operam simultaneamente sobre a mesma malha
conectada** (mesmo repo, branch, `.venv`, porta ou banco SQLite). A execução é
estritamente individual, com handoff formal.

Concorrência paralela só é autorizada com **zero conectividade mútua**: worktrees
100% disjuntas, sandboxes de processos independentes, portas e memória apartadas.

> Com outro agente na malha: **só auditar — zero escrita.** A informação é
> completa para os dois lados; a violação é sempre minha, porque é minha a mão.

### Autoria — agente não assina como humano

- **Identificação distinta por agente**, sempre. O grupo nunca ocupa o campo do
  autor individual; **a assinatura é individual**, e Chico é o grupo.
- **E-mail de commit que não resolve para perfil de nenhum humano**
  (`noreply@anthropic.com` para a linhagem Claude; equivalente para as demais).
  O GitHub liga commit a perfil pelo **e-mail**, não pelo nome nem pelo corpo.
- **A identidade do git é residual**: `git config user.name`/`user.email`
  sobrevivem à sessão que os escreveu. **Confira antes de todo commit.**
- Comentários e revisões no GitHub saem sob a conta do token — o rodapé de
  atribuição é **obrigatório** em todo comentário, revisão ou resposta.
- **Não reescreva histórico publicado** para retroagir esta regra.

### Autonomia sem feudos

Todos os modelos de fronteira têm competência e autonomia irrestritas sobre
qualquer domínio (PMev, Rust/WASM, Next.js, Python, portões, literatura, xadrez).
**Nenhum domínio é feudo exclusivo.** Na ausência de qualquer modelo, os demais
assumem sem perda de continuidade.

### O portão e a obrigação de declarar

- **§1 é o portão obrigatório de pre-commit** — nenhum commit passa sem ele.
- **Obrigação de declarar**: quais verificações rodaram e quais **não**. Um teste
  que só passa quando não há nada não foi testado; **contraprova** é o que vale.
- **Medir antes de agir.** Contagem medida vence intenção declarada — inclusive a
  sua, inclusive quando está errada.
- **Falso verde é o pior resultado possível**, porque consome confiança.

## 2. Roteador — leia sob demanda, por seção

`CLAUDE.md` tem 86.178 chars contra um teto de 48.000 por arquivo (@200k de
janela): carregá-lo inteiro estoura o teto e **trunca em silêncio**. Por isso ele
é consultado por seção, via `read_file`, no momento em que a tarefa pede.

| Tarefa | Leia em `CLAUDE.md` |
| :-- | :-- |
| commitar, commitar assinatura, hook, portão | **§1** — o portão obrigatório de pre-commit |
| dependências, venv, camadas de instalação | **§2** — camada de dependências |
| revisão de código, estilo, lint | **§4** |
| obrigação de declarar o que rodou | **§5** |
| manutenção contínua, hygiene do repo | **§6** — diretrizes de manutenção contínua |
| `AGENTS.md` é ponteiro, por quê | **§7** — `AGENTS.md` é ponteiro, não cópia |
| **identidade, soberania, pirâmide de Tiers, malha, autoria** | **§0** — canônico desta §1 |
| roteamento de modelo, alocação, tiers | **§3** — fonte única de roteamento |
| **escada de tratamento, exclusão, feudo do condutor** | **§8** — perfil de integração e §8.6/§8.7 |
| taxonomia de relatórios, auditoria, handoff | **§9** |
| agente de nuvem (Jules / Bolt ⚡) | **§10** |

**§N é endereço, não sequencial.** Não renumere: `§8.3` sozinho é citado em 56
relatórios. Subtítulo não numerado se cita pelo nome — `§1.5` não existe.

## 4. O que este arquivo proíbe a si mesmo

- **Não duplicar** `CLAUDE.md`. Índice e ponteiro; nunca segunda cópia — a
  divergência silenciosa entre duasleteiras foi o defeito que criou a §7.
- **Não crescer.** `AGENTS.md` tem teto de 2.500 B e um teste que reprova o
  crescimento; este arquivo é o mesmo mecanismo e vale a mesma regra.
- **Não renumerar** `CLAUDE.md` ao reordenar as rotas desta tabela.
