## 2026-09-27 - Remove branching overhead and iterator allocation in CFR hot loop
**Learning:** Using the nullish coalescing operator (`?? 0`) on bounded `TypedArray` accesses (like `Float32Array`) in JavaScript causes significant performance degradation (~30x penalty) in hot loops due to unnecessary branching/type-checks. Bounded access always returns a primitive number, never `undefined`. Furthermore, using `for...of` loops over `TypedArray` objects incurs substantial iterator overhead (~10x penalty) compared to traditional `for` loops.
**Action:** Never use `?? 0` as a fallback on array bracket accesses within performance-critical hot loops when working with TypedArrays, and always favor standard primitive `for` loops (`for (let i = 0; i < arr.length; i++)`) over `for...of` or other iterators to maximize execution speed.
